# AGENTS.md

## 프로젝트 목적

Windows 바탕화면 위에 투명하게 표시되는 캐릭터가 사용자가 선택한 회사의 주가 등락에 따라 서로 다른 PNG 프레임 애니메이션을 재생하는 데스크톱 앱을 개발한다.

## 필수 기술 스택

- Tauri 2
- React
- TypeScript
- Vite
- Rust
- PNG frame animation
- Vitest
- Cargo test

## 작업 원칙

- 작업 전 관련 문서를 읽고 현재 단계의 완료 조건을 확인한다.
- 큰 변경 전 구현 계획을 작성하고 사용자 승인을 기다린다.
- 사용자가 명시적으로 승인하기 전에는 다음 개발 단계로 넘어가지 않는다.
- 한 작업 단위에서 필요한 파일만 수정한다.
- 기존 사용자 그래픽을 임의로 편집, 삭제, 이름 변경하지 않는다.
- 애니메이션 프레임 수를 TypeScript, CSS 또는 Rust에 하드코딩하지 않는다.
- 애니메이션 프레임은 manifest의 `frames` 배열을 단일 진실 공급원으로 사용한다.
- 실제 주가 데이터 제공자와 Mock 제공자는 동일한 내부 모델을 반환해야 한다.
- API 응답 원본 형식을 UI 코드에 직접 노출하지 않는다.
- API 키, 토큰, 계좌번호, 비밀번호를 소스 코드나 일반 설정 파일에 저장하지 않는다.
- 오류 발생 시 앱이 종료되지 않고 `idle` 또는 정적 대체 이미지로 복구되어야 한다.
- 사용자에게 보이지 않는 실패를 만들지 말고 개발 모드 로그에 원인을 기록한다.
- 삭제 명령과 프로젝트 루트 밖 파일 접근은 수행하지 않는다.
- 빌드·테스트 명령 실행 전 실행할 명령과 목적을 알린다.

## 설계 규칙

### 계층 분리

- React: 화면, 입력, 프레임 렌더링
- Rust: 네이티브 창, 주가 통신, 설정 및 보안 처리
- State machine: 주가 상태와 애니메이션 ID 매핑
- Asset manifest: 프레임 목록, FPS, 반복 여부, 다음 애니메이션

### 상태

기본 상태:

- `STRONG_UP`
- `UP`
- `FLAT`
- `DOWN`
- `STRONG_DOWN`
- `MARKET_CLOSED`
- `DATA_ERROR`

순간 이벤트:

- `SURGE`
- `DROP`
- `TICK_UP`
- `TICK_DOWN`

### 상태 우선순위

1. DATA_ERROR
2. MARKET_CLOSED / HOLIDAY
3. SURGE / DROP
4. TICK_UP / TICK_DOWN
5. 기본 등락 상태
6. 일상 행동

## 품질 기준

- TypeScript `strict` 사용
- Rust 오류를 무조건 `unwrap()`으로 처리하지 않는다.
- 핵심 상태 계산은 순수 함수로 작성한다.
- 경계값 테스트를 반드시 추가한다.
- 프레임 0개, 1개, 여러 개, 누락 파일 상황을 테스트한다.
- 구현 종료 후 실행한 명령과 결과를 요약한다.
- UI 작업 종료 시 스크린샷 또는 화면 검증 결과를 제공한다.
